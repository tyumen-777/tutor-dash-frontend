# Tutor Dash

CRM-система для школ иностранных языков и образовательных центров. Проект помогает владельцу, администратору и преподавателям видеть состояние школы в одном интерфейсе: деньги, учеников, оплаты, занятия, успеваемость, риски оттока и загрузку команды.

## Задача продукта

Языковая школа обычно ведет сразу несколько процессов: заявки, пробные уроки, группы по уровням, индивидуальные занятия, абонементы, долги, посещаемость, домашние задания, прогресс учеников и зарплаты преподавателей. Tutor Dash собирает эти процессы в единую CRM, чтобы школа меньше жила в таблицах и переписках, а больше управляла понятными показателями.

## Что уже заложено в интерфейсе

- Главный дашборд с выручкой месяца, количеством активных учеников, долгами и риском ухода.
- Блок приоритетных действий: пробные уроки без follow-up, ученики без следующего занятия, группы с просадкой посещаемости.
- Воронка продаж от новых лидов до оплаты.
- Расписание дня со статусами занятий и заполненностью групп.
- Карточки нагрузки преподавателей и удержания учеников.
- Список учеников с сортировкой, действиями и переходом в профиль.
- Профиль ученика: контакты, родитель, уровень, цель обучения, преподаватель, ближайшее занятие, остаток занятий, посещаемость, история уроков, оплаты и предпочтительное время.
- Базовая навигация по разделам: обзор, ученики, занятия, финансы, расписание, материалы и настройки.

## Полезный функционал для развития CRM

### Ученики и обучение

- Карточка ученика с уровнем CEFR, языком, целью, форматом обучения и историей переходов между уровнями.
- Учет групповых, индивидуальных, парных и интенсивных занятий.
- Журнал посещаемости с автоматическим списанием занятий из абонемента.
- Отслеживание прогресса: темы уроков, результаты тестов, домашние задания, рекомендации преподавателя.
- Сигналы риска ухода: пропуски, отсутствие следующего урока, низкая активность, заканчивающийся абонемент.
- Перевод ученика между группами с сохранением истории оплат, посещаемости и прогресса.

### Финансы

- Учет поступлений, расходов, долгов и возвратов.
- Абонементы и пакеты занятий: остаток уроков, заморозки, переносы, срок действия.
- Счета и напоминания об оплате.
- Отчеты по выручке: по преподавателям, группам, языкам, филиалам и периодам.
- Автоматический расчет зарплаты преподавателей по ставке, проценту или количеству проведенных уроков.

### Расписание и операционка

- Календарь занятий с повторяющимися уроками, переносами и отменами.
- Проверка конфликтов по преподавателю, ученику, аудитории и времени.
- Учет аудиторий, онлайн-ссылок и формата занятия.
- Рабочий день преподавателя: список занятий, отметка посещаемости, комментарии по уроку.
- Материалы и база знаний для преподавателей.

### Продажи и коммуникации

- Воронка заявок: новый лид, пробный урок, ожидание оплаты, активный ученик, отказ.
- История коммуникаций с учеником или родителем.
- Напоминания о занятиях, оплатах и продлении абонемента.
- Интеграции с мессенджерами, сайтом и формами заявок.
- Сегменты для повторных продаж: закончили курс, давно не посещали, готовы к следующему уровню.

### Кабинеты и роли

- Роли владельца, администратора, преподавателя, ученика и родителя.
- Личный кабинет ученика или родителя: расписание, остаток занятий, оплаты, домашние задания, прогресс.
- Ограничение доступа к финансовым данным и персональной информации.
- Уведомления для разных ролей: долги для администратора, уроки для преподавателя, прогресс для родителя.

### Аналитика

- План-факт по выручке и продажам.
- Конверсия из заявки в оплату.
- Удержание по преподавателям, группам, языкам и форматам.
- Загруженность преподавателей и групп.
- Прогноз выручки и список платежей, которые нужно собрать в ближайшие дни.

## Ориентиры по аналогам

Перед составлением требований были изучены русскоязычные и англоязычные CRM для языковых школ и образовательных центров. У сильных решений повторяются одни и те же идеи:

- урок является основной единицей учета;
- CRM должна связывать расписание, посещаемость, оплату и зарплату преподавателя;
- важны уровни языка, история прогресса и готовность к переходу на следующий уровень;
- школе нужны автоматические напоминания об оплатах, занятиях и продлении абонемента;
- владельцу нужен дашборд по деньгам, долгам, продажам, удержанию и нагрузке преподавателей;
- ученику или родителю полезен личный кабинет с расписанием, оплатами, домашними заданиями и результатами.

## Генерация API-клиента

Orval генерирует типизированные Axios-функции и хуки TanStack Query из
OpenAPI-документа. По умолчанию схема загружается с
`http://localhost:4000/api`, а запросы приложения отправляются на
`NEXT_PUBLIC_API_URL`.

```bash
cp .env.example .env
npm run api:generate
```

URL схемы переопределяется переменной `OPENAPI_URL`. Если она указывает на
локальный файл, для автоматической перегенерации при его изменении можно
использовать `npm run api:watch`.

Сгенерированные файлы появятся в `src/lib/api/generated` и уже будут содержать
React Query hooks. Имя хука строится из `operationId` в OpenAPI. Например, если
операция имеет `operationId: getStudents`, клиентский компонент сможет вызвать:

```tsx
'use client'

import { useGetStudents } from '@/lib/api/generated/students/students'

export function Students() {
	const { data, isPending, error } = useGetStudents()

	if (isPending) return <p>Загрузка...</p>
	if (error) return <p>Не удалось загрузить учеников</p>

	return <pre>{JSON.stringify(data, null, 2)}</pre>
}
```

Точный путь импорта зависит от тегов OpenAPI, а имя хука — от `operationId`.
Сгенерированный код изменять вручную не нужно: общие настройки Axios находятся
в `src/lib/api-client.ts`, а кэш React Query настраивается в
`src/app/providers/query-provider.tsx`.
